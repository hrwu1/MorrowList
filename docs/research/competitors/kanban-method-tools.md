# Kanban-method purist tools vs MorrowList (research, 2026-09-02)

Scope: Businessmap (ex-Kanbanize), Planview AgilePlace (ex-LeanKit), Kanban Tool, KanbanFlow, SwiftKanban (Nimble), Kanban Zone, Personal Kanban (Jim Benson). Method sources: Kanban Guide v2025.5, Open Guide to Kanban 2025.7, Kanban University, Personal Kanban secondary sources (personalkanban.com returned 403; agilehumans.city interview and Wrike/Any.do guides used instead).

Access notes: knowledgebase.businessmap.io, kanbanzone.com, kanbanflow.com/features/\* subpages and the article bodies on success.planview.com could not be fetched (403/404/JS-rendered). Where only the doc title or a vendor summary page was reachable, the row says so.

## 1. Method checklist (what a board "must" support)

| Requirement                                                                                                                                                                                                                                                                            | Source / quote                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |

| Control WIP (limit per state, per person, or ranges/min-max; "painter's tape spots", "WIP control numbers, or WIP control ranges")                                                                                                                                                     | [KG], Open Guide [OG]                                                                                                |

## 3. Gaps MorrowList should consider

Rating: Table-stakes (T) / Differentiator (D) / Nice-to-have (N) / Niche (X).

Cheap wins from existing `activity_events` (status-change history). Every mutation already writes an immutable event, so the following need no new write path, only a read model:

1. **Cycle time / lead time per task and percentiles (T→D for a personal tool).** The Guide makes cycle time and throughput mandatory metrics [KG]. Compute from the first event entering a status whose category is "in progress" (start) to the "done" event (finish); lead time from creation/commitment. Kanban Tool ships this on its free plan [KT-AN]; KanbanFlow paywalls it [KF-PRICE]. Showing "you usually finish tasks like this in N days" is the personal-scale SLE.
2. **Work item age on cards + aging visualization (T).** "Ensuring work items do not age unnecessarily" is core active management [KG]; Kanban Zone calls card aging the signal that catches slow cards "while still in play, rather than waiting to see cycle time" [KZ-AGING]. Age = now minus entry into current column, available from events. Render as a badge and a fade/border tint at 2–3 configurable thresholds.
3. **Throughput + CFD (D).** Daily counts per status over time can be replayed from events. CFD is offered by five of six tools [BM-CFD][KT-AN][KF-PRICE]. For an individual, a weekly throughput number plus "done this week" (Personal Kanban's "reflect on Done") is the useful surface.
4. **Aging WIP chart with percentile lines (D).** Businessmap's chart places each open item in its column against cycle-time percentiles [BM-AGING]; SwiftKanban has it [SK]. Once (1) and (2) exist, this is one chart.
5. **Monte Carlo "when will these N tasks be done" (N).** Businessmap samples historical daily throughput [BM-MC]. Cheap once throughput history exists, but forecasting value for one person is modest.

Board-model gaps:

6. **Blocker flag with reason and blocked time (T).** The Open Guide says the DoW "should include a policy for defining Blockers and signaling them" [OG]; AgilePlace requires a reason and keeps blocked history [PV-BLOCK]; Leopold's blocker clustering needs reason + duration [BM-BC]. MorrowList's "Blocked" column loses where the task was; a flag preserves the column and is queryable (`blocked` filter already exists in URL params). Blocked time falls out of block/unblock events.
7. **Explicit column policies (T).** "Make policies explicit" [KU]; Kanban Tool shows a description behind an info icon [KT-BOARD]; Kanban Zone enforces exit criteria [KZ-SEARCH]. A Markdown `policy` field on workflow status, shown on hover/expand, is small and needed anyway for the planned workflow-editing feature.
8. **Sub-columns / queue states (D for purists, N for most).** Doing/Done splits make hand-offs visible [KT-BOARD]. For a single-user tool, a cheaper equivalent is a per-status "queue" category (Ready-type columns) so cycle time excludes waiting.
9. **WIP limit options (N).** Per-person and per-lane limits matter for teams [BM-SWIM][KT-BOARD]; for one person a single board-wide "Doing" limit of 2–3 is what Personal Kanban prescribes [PK-AH][PK-ANYDO]. Consider a workspace-level "max in progress across projects" — none of the tools' per-board limits catch cross-project overload, which is the personal-user failure mode.
10. **Swimlanes / classes of service (N).** Expedite/fixed-date/standard/intangible [BM-COS]. MorrowList's priority field can stand in for class of service; a "fixed date" class is largely due-date. Swimlanes by project on a cross-project board would be the personal-relevant variant (the planned "All Tasks" view).
11. **Card types/colors, templates, checklists, recurring cards (T for daily use).** Every competitor has these; KanbanFlow has recurring tasks and Pomodoro on its free plan [KF-PRICE]. Checklists and dependencies are already planned; recurring cards are only a long-term idea.
12. **Time tracking / Pomodoro (N/X).** KanbanFlow's niche; reviewers of Kanban Tool praise its time reports [SEL]. Not method-required; skip unless positioning toward focus/productivity.
13. **Automation rules (N).** Vendors gate them (Businessmap add-on, Kanban Tool Enterprise) [BM-PRICE][KT-FEAT]; the outbox events plus planned webhooks would give the same in a hackable form.
14. **Webhooks + export (T for a self-hosted, API-first tool).** All six offer export; AgilePlace exports full board history [PV-DOC]. Exposing activity events via API/CLI (`morrow task history`) is the differentiator: the zipdo roundup faults Kanban Tool for "exports oriented to board snapshots rather than deep history" [ZIPDO].

## 4. What users complain about (opportunities)

- **Price and minimum seats for individuals.** Businessmap: "no free version available for individuals", costly for small teams, automation is a paid upgrade, 15-seat minimum reported by third parties [BM-REV][BM-PRICE2]. SwiftKanban and AgilePlace: "price can be quite high for small organizations" [SK-REV][PV-REV]. A free self-hosted tool with method-grade metrics has no direct competitor here.
- **Complexity / learning curve.** Businessmap "not easy to understand at the beginning" [BM-REV]; SwiftKanban "could be more user friendly", "many ways to do some things" [SK-REV]; Kanban Zone "customizing the boards can be tricky", boards "very cluttered" [KZ-SA]. Opportunity: defaults that already embody the method (WIP limit, aging, policies) with no configuration.
- **Analytics quality.** SwiftKanban: "Analytics part is very bad, the configuration of reports is not good", CFD not across lanes [SK-REV]; Businessmap reporting has "a lot of room for improvement" [BM-REV]; KanbanFlow "reporting… a bit complicated" [KF-SA]; Kanban Tool "reporting should be enhancement as we need data in Excel" [KT-SA]. Opportunity: few, correct, exportable metrics.
- **Performance and mobile.** Businessmap "extremely slow" with many cards, "no mobile application" [BM-REV]; KanbanFlow mobile sync "sometimes bad", "lagged a lot" [KF-SA]; SwiftKanban wants native push notifications [SK-REV].
- **Dated UI / weak text formatting.** KanbanFlow "design is a bit dated", hard to add images/links without markup [KF-SA]; Kanban Tool task display "kind of obsolete", "settings are a bit hidden" [KT-SA]; AgilePlace "UI is a little dull", hard to delete cards without admin [PV-REV].
- **Integrations.** Businessmap "most integrations are done via 3rd party software like Make or Zapier" [BM-REV]; SwiftKanban "lacks more integrations" [SK-REV]. Opportunity: first-class API/CLI/webhooks.
- **Search / archived cards.** Businessmap: finding archived cards takes "5 to 10 minutes" [BM-REV]; KanbanFlow filters/tags "need to be improved" [KF-SA]. MorrowList search and tags are still unbuilt.
