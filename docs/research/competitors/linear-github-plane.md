# Competitor research: Linear, GitHub Projects, Plane (+ Height, Shortcut, Huly)

Date: 2026-09-02. Segment: developer-oriented issue trackers with Kanban boards. Baseline: `BASELINE.md`.
Claims are sourced by number (see §5). "unverified" = could not confirm from a primary source in this session.

## 1. Product snapshots

**Linear** — Cloud-only, closed-source issue tracker for product/engineering teams; "more than 40,000 companies" [L-price]. Free (unlimited members, 2 teams, 250 issues, includes Agent platform + Linear Agent), Basic $10, Business $16/user/mo (unlimited teams, guests, Triage Intelligence, Code Intelligence, Loops, Insights, SLAs), Enterprise custom [L-price]. 2026 has been an all-in bet on AI: Linear Agent (Mar 24), Code Intelligence (May), Linear Diffs (May), coding sessions with Claude Code/Codex (Jun), Loops recurring automations (Jul), sandboxed coding environments (Aug) [L-cl]. No self-hosting [PL-vs-L].

**GitHub Projects (v2)** — Free planning layer over GitHub Issues/PRs; table/board/roadmap layouts, up to 50 custom fields [GH-about], 50,000 items per project (was 1,200) and Insights now on all plans [GH-limits, GH-ga]. 2025 GA'd sub-issues, issue types, AND/OR search [GH-ga]; 2026 added advanced search in project views (Jul) and agent sessions (Copilot/Claude/Codex) visible in board/table (Mar) [GH-adv, GH-agent]. Self-host only via GitHub Enterprise Server. Official `gh project` CLI [GH-cli].

**Plane** — Open-core, AGPL-3.0, 58.8k GitHub stars, "Open-source Jira, Linear, Monday, and ClickUp alternative" [PL-repo]. Cloud Free (12 seats), Pro $6, Business $13/seat/mo, Enterprise Grid; all plans available self-hosted (Docker Compose or Kubernetes/Helm) [PL-price, PL-selfhost]. Gating: work item types/custom properties, wiki, time tracking, GitHub integration = Pro; templates, recurring items, intake forms/email, automations = Business; webhooks/scripts in automations = Enterprise [PL-price, PL-auto, PL-gh]. Plane AI (Ask/Build/Autopilot, MCP connectors, Skills, PQL), hosted MCP server, native desktop app (Jul 2026 v3.0) [PL-ai, PL-mcp, PL-cl].

**Height** — Dead. Announced 2025-03-28, shut down 2025-09-24, data deleted [H-creativerly, H-search]. Founder gave no specific reason; commentators attribute it to losing to Linear even after the AI-centric "autonomous" 2.0 [H-creativerly]. Users scattered to Linear (which imports Height), Shortcut (CSV only), ClickUp, Notion [H-search, H-shortcut]. Lesson: AI-first positioning did not save a tracker that lacked Linear's speed/GitHub depth; some 2026 listicles still (wrongly) recommend it [SF].

**Shortcut / Huly (glance)** — Shortcut: Free ≤10 users, Team $8.50, Business $12; stories/epics/iterations, Korey AI agent, MCP server [SC-price]. Huly: EPL-2.0, 27.5k stars, "all-in-one" tracker+chat+docs+video with bidirectional GitHub Issues/Projects sync; README says the hosted service is shutting down and urges self-hosting, though the pricing page still lists plans (flat-rate, not per-seat) [HU-repo, HU-price] — status partially unverified.

## 3. Gaps MorrowList should consider

Rated: **T** = table-stakes, **D** = differentiator, **N** = nice-to-have, **X** = niche.

1. **Labels/tags, search, sub-task UI, saved views (T).** Every competitor has these; ML has them only as plans. Linear's sub-issue "parent auto-close" and filter-by-level are the polished versions [L-sub].
2. **Board grouping + swimlanes + hide/collapse columns (T).** All three let you re-pivot a board (assignee/priority/label/project) and add a second axis. Linear ties list and board ordering together so switching layouts never loses your order [L-board, L-display]. For a personal tool, group-by project with a status swimlane (or vice versa) is the obvious first step.
3. **Dependencies (blocked-by/blocks/related/duplicate) (T for the "quality" positioning).** Linear shows orange/red flags in the sidebar and auto-converts to "related" on resolution; Plane has the same four types [L-rel, PL-props]. ML already has a `Blocked` status category, which is the weaker model — a _relation_ explains _why_.
4. **Command palette + single-key shortcuts (D — this is the core of "Linear feels fast").** Linear's speed is two things: (a) a local database in IndexedDB with optimistic writes and WebSocket delta sync, so an update takes milliseconds vs ~300 ms for CRUD apps [PERF, SYNC]; (b) keyboard-first design — `C` create, `X` select, `G I` inbox, `/` search, Cmd+K for every action, none remappable [L-kbd]. Third-party reviewers count "50+ shortcuts" and "60 fps" as its differentiators [OH]. ML already has optimistic updates + conflict rollback; adding a Cmd+K palette that reuses the same command layer as the CLI would be cheap and on-brand.
5. **Local-first/offline with a real sync engine (D).** Nobody in this segment except Linear does it, and Linear can't be self-hosted. A self-hosted Postgres + client-side replica is the combination none of them offer [PL-vs-L, PERF]. Planned PWA shell is a start; the outbox + version fields already in ML are the right foundation.
6. **Agent-friendliness: CLI, MCP, delegate model (D — ML's stated first-class surfaces).** Evidence users want it: Linearis exists because the official MCP burned ~13k tokens for 20+ tools of which the author used 3–4; a bash CLI with JSON output and a single `usage` command was preferred [CLI-linearis]; schpet/linear-cli ships an "agent skill" and auto-creates branches [CLI-schpet]. Linear models agents as **delegates, not assignees** ("humans maintain ownership"), with sessions, activities, and `AgentSessionEvent` webhooks [L-agents]; GitHub shows agent sessions with queued/working/waiting-review state on the board [GH-agent]. ML can differentiate with: compact `morrow usage` for agents, a delegate field + session/activity log per task, and webhook delivery from the existing outbox.
7. **Webhooks + PR→status automation (T for dev users).** Linear: HMAC signature, timestamp replay guard, retries at 1m/1h/6h, `updatedFrom` diffs [L-wh]. Magic words (`fixes ML-12`) and per-branch rules are the expected shape [L-gh]. Plane gates GitHub sync behind Pro — an opening for a free self-hosted tool [PL-gh].
8. **Workflow editing (T).** Linear's model — fixed categories (backlog/unstarted/started/completed/canceled/duplicate), unlimited named statuses within them, one default status — is the right constraint; ML already has categories [L-wf]. Add auto-close-stale and auto-archive.
9. **Estimates, cycles, insights (N for personal; T for teams).** Linear's cycle auto-rollover + cooldown + capacity dial and Insights' cycle-time/lead-time charts are why teams pay for Business [L-cycles, L-ins]. GitHub made Insights free on all plans in 2025 [GH-limits]. For a personal-first tool, a lightweight "week" cycle with rollover would be the honest version.
10. **Bulk select/edit + undo (T).** Linear: `X`, Shift-arrows, Cmd-A, Option-↑↓ to move [L-select]. ML has this planned.
11. **Timeline/roadmap and calendar views (N).** Linear deliberately has no issue-level Gantt and gets criticized for it [SIIT]; Plane and GitHub have it. ML's due-date model supports a calendar cheaply.
12. **Custom fields / item types (X for personal, T for teams).** Linear's refusal to add them is a recurring complaint (single project, single assignee, no required fields) [SIIT, PL-vs-L]. Not worth it for the MVP persona.
13. **Triage/Intake, SLAs, customer requests (X).** Team/B2B features; skip.
14. **Import/export (N→T once users migrate).** Linear imports from Jira/GitHub/Asana/Shortcut plus a CLI importer; export is capped CSV [L-import, L-export]. ML's JSON export is planned; a Linear/GitHub importer would target the Height-style migration moment.

## 4. What users complain about (opportunities)

- **Linear is opinionated to the point of rigid**: single assignee, single project per issue, no custom/required fields, no issue-level Gantt, weak reporting, no free viewer role, cloud-only, separate AI credit costs; "starting to resemble the tools it set out to replace"; slow first-page loads and sync bugs on rapid sequential edits reported [SIIT, G2-search, SF]. Per-seat cost "scales unfavorably past 25 seats" [SF]. Everything worth having (Insights, SLAs, Triage Rules, Loops, Code Intelligence) is Business-tier [L-price]. → ML: keep the opinionated core but self-host, no seat pricing, transparent data.
- **GitHub Projects is thin**: the 1,200-item ceiling drove a well-known complaint (consolidating TODOs from 100+ repos) [GH-1200]; now 50k, but no human IDs, board columns only from single-select/iteration fields, no auto-rollover for iterations, GraphQL-only API where "you cannot add and update an item in the same call" and assignees/labels need separate mutations [GH-api, GH-iter]. Dependencies still unverified. → ML: REST + OpenAPI + CLI already beats this for scripting.
- **Plane is heavier and paywalled sooner than the "open-source Linear" pitch suggests**: reviewers call the UI "noticeably heavier than Linear's famously snappy keyboard-driven UI" [SEARCH-cmp]; a user reported UI lag until cache cleared [PL-g2-search]; GitHub sync, custom fields, and wiki are Pro; automations Business; webhooks-in-automations and multiple workflows Enterprise; hosted MCP is cloud-only; AI web search unavailable for self-hosted custom models [PL-price, PL-auto, PL-mcp, PL-ai]; self-hosting "requires DevOps expertise" [CAN, OH]. → ML: a truly complete self-hosted edition with speed as the headline.
- **MCP token bloat**: official MCP servers with 20+ tools cost ~13k context tokens; agent users prefer small CLIs with JSON [CLI-linearis]. → ML: keep `morrow` compact and self-describing.
- **Vendor risk**: Height (2025) and Huly's hosted service (per README) show that small hosted trackers die; users then migrate via CSV with lossy imports [H-shortcut, HU-repo]. → ML: self-hosting + JSON export is a retention argument.
