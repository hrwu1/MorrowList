# Competitor research: Jira (Atlassian) — 2026-09-02

Scope: Jira Cloud (Jira Software + Jira Work Management unified as "Jira"; Atlassian now calls issues "work items" and projects "spaces"). Compared against MorrowList's baseline (BASELINE.md).

## 1. Product snapshot

- **Who uses it**: software/agile teams first, increasingly business teams; Atlassian markets a "Personal task tracker" template, but reviewers consistently judge it overkill for individuals and non-technical teams ([TaskRhino review](https://www.taskrhino.ca/blog/jira-review/), [Siit Linear-vs-Jira](https://www.siit.io/tools/comparison/linear-vs-jira)).
- **Pricing (Cloud, July 2026)**: Free $0 (10 users, 2 GB, ~100 automation runs/mo, community support); Standard $7.91/user/mo (250 GB, 1,700 runs/mo shared); Premium $14.54/user/mo (unlimited storage, 1,000 runs/paid user/mo, Plans, sandbox, archiving, 99.9% SLA); Enterprise custom, annual only ([resolution.de](https://www.resolution.de/post/jira-pricing-plans/), [Atlassian plan comparison](https://support.atlassian.com/jira-cloud-administration/docs/explore-jira-cloud-plans/), [Jira Premium](https://www.atlassian.com/software/jira/premium)). Note: Atlassian's own plan page now describes automation in "steps per user per month" (Free 150 steps/subscription; Standard 400; Premium 750; Enterprise 1,000) — the run-vs-step model appears to be changing in 2026; treat exact quotas as in flux.
- **Scale signals**: Capterra 4.4/5 from 15,468 reviews (ease of use 4.1) ([Capterra](https://www.capterra.com/p/19319/JIRA/reviews/)); G2 4.3/5, 6,000+ reviews (cited via [TaskRhino](https://www.taskrhino.ca/blog/jira-review/); G2 page itself blocked fetch). Marketplace "3,000+ integrations" ([Jira features](https://www.atlassian.com/software/jira/features)). Single Cloud site supports 100,000 users.
- **2024–2026 direction**: Rovo AI everywhere (agents, natural-language search/automation/formulas), rebuilt List/Board/Timeline on a shared foundation, Goals via Atlassian Home, Capacity view, Formula fields ([Summer 2026 release](https://www.atlassian.com/blog/development/jira-summer-release), [community list of 15 features](https://community.atlassian.com/forums/Jira-articles/Introducing-the-Jira-2026-Summer-Release/ba-p/3268349)).

## 3. Gaps MorrowList should consider

Ratings: **Table-stakes** (expected by anyone coming from Jira/Trello), **Differentiator** (personal-first angle Jira does badly), **Nice-to-have**, **Niche** (team/enterprise; avoid copying).

1. **Column/workflow editing (add, rename, reorder, map status→column)** — Table-stakes. Every Jira board allows this inline; reviewers cite "flexibility in creating workflows" as the top pro ([Capterra](https://www.capterra.com/p/19319/JIRA/reviews/)). Keep it inline-on-board like team-managed Jira; skip schemes.
2. **Subtasks UI + parent/child on cards and lists** — Table-stakes. Jira's 2026 release put subtasks on cards and hierarchy in List; "break down big projects into clear tasks" is Atlassian's first feature pitch ([features](https://www.atlassian.com/software/jira/features)). Two levels (task→subtask) are enough; Jira's Epic/Initiative levels are Niche.
3. **Dependencies (blocks / is blocked by) with visual cue** — Table-stakes for a Kanban tool with a Blocked column. Jira draws them on the timeline and auto-flags conflicts.
4. **Swimlanes** — Differentiator for personal use if done simply (by project, by due-bucket, by priority). Jira's JQL swimlanes are Niche; "by parent" and "expedite" lanes are the useful part ([swimlanes](https://support.atlassian.com/jira-software-cloud/docs/configure-swimlanes/)).
5. **Saved views / quick filters** — Table-stakes. Jira's quick filters (toggle buttons) + saved filters + 2026 shared custom views are heavily used; MorrowList already has URL-param filters, so persisting them as named views is cheap.
6. **Structured query** — Nice-to-have. Full JQL is over-complex for individuals (JQL is a top learning-curve complaint), but a small filter grammar exposed through CLI/API (`morrow task list --where`) is a natural fit for MorrowList's API-first positioning.
7. **WIP min + column-count options, days-in-column ageing dots** — Nice-to-have. Ageing indicator is cheap and personal-relevant (stale tasks). Min limits are Niche.
8. **Card display config (extra fields, color by priority/project)** — Nice-to-have; Jira restricts it to company-managed boards, so users on Free/team-managed already live without it.
9. **Calendar view + start dates** — Table-stakes for personal planning (Jira's personal template leads with Board/List/Calendar). Timeline/Gantt is Niche.
10. **Labels/tags and custom fields** — Tags: Table-stakes (already planned). Custom fields: Nice-to-have, cap at a few types; Jira's field sprawl ("87 fields to file a bug") is the #1 bloat complaint ([dev.to](https://dev.to/teamcamp/why-developers-hate-jira-and-10-best-jira-alternatives-1hl1)).
11. **Recurring tasks** — Differentiator. Jira has none natively and forces users into automation rules that eat quota ([recurrence doc](https://support.atlassian.com/cloud-automation/docs/automatically-clone-an-issue-when-done/)); native recurrence is a clear win for the personal persona.
12. **Undo + trash for tasks** — Differentiator already in hand: Jira cannot restore a deleted work item at all ([guide](https://community.atlassian.com/forums/App-Central-articles/Deleted-Work-Items-in-Jira-The-Complete-Guide/ba-p/3113452)). Add undo for bulk ops (Jira has none).
13. **Bulk edit** — Table-stakes (planned). Jira caps at 1,000, excludes summary/description; do better with undo.
14. **Keyboard shortcuts (C, J/K, O, ?)** — Table-stakes for the developer persona; Linear's speed/keyboard-first UX is the main reason teams leave Jira ([Siit](https://www.siit.io/tools/comparison/linear-vs-jira)).
15. **Lightweight automation** — Nice-to-have. Simple "when moved to Done → complete; when due passes → flag" rules. Jira's full rule builder + quotas is Niche/bloat.
16. **Activity history, comments, attachments** — Comments/attachments Niche for single user until team persona; activity history UI Table-stakes (already recorded in DB).
17. **Reports: cumulative flow, control chart, throughput** — Nice-to-have (Kanban-native, individual-relevant: "how long do my tasks sit in In Progress?"). Sprint/velocity/burndown: Niche, skip.
18. **Notifications / reminders** — Table-stakes for due dates (Jira has email digests; personal tools need due reminders). Notification schemes: Niche.
19. **Import/export (CSV, JSON)** — Table-stakes; a Jira CSV importer would directly target switchers.
20. **Webhooks + API tokens** — Differentiator vs Jira's expiring app webhooks and points-based rate limits; MorrowList already has API keys.
21. **Templates / onboarding** — Nice-to-have: 2–3 starter workflows (Personal Kanban, Simple To-do, Software) rather than Jira's dozens.
22. **AI features** — Nice-to-have, optional and local/self-hosted friendly; Jira gates most behind Rovo/Standard+. Don't lead with it.
23. **Mobile/PWA/offline** — Table-stakes for personal use; Jira's mobile has "limited offline" ([ToolStack](https://toolstackpm.com/tools/jira/features/mobile-app)), so a real offline PWA is a Differentiator.
24. **Goals, Plans, capacity, components, versions, workflow validators/post-functions, hierarchy above Epic, dashboards/gadgets** — Niche; explicitly avoid.

## 4. What users complain about (opportunities)

Note: Reddit could not be fetched directly in this session; complaints below come from Capterra (15k reviews), G2 summaries via TaskRhino, dev.to, and comparison articles.

- **Overwhelming complexity / steep learning curve (2–4 weeks)** — the most repeated con on Capterra: "crowded with many menus, boards, filters, projects, and configuration options"; setup "extremely clunky" until you learn its logic ([Capterra](https://www.capterra.com/p/19319/JIRA/reviews/), [TaskRhino](https://www.taskrhino.ca/blog/jira-review/)). → MorrowList: zero-config default board, one task model, no schemes.
- **Slow / bloated UI** — "load times measured in coffee breaks"; Jira's own 2026 release brags of 45%/48%/22% speedups, confirming the baseline was slow ([dev.to](https://dev.to/teamcamp/why-developers-hate-jira-and-10-best-jira-alternatives-1hl1), [Summer 2026](https://www.atlassian.com/blog/development/jira-summer-release)). Linear's sub-100 ms interactions are the benchmark reviewers use ([Siit](https://www.siit.io/tools/comparison/linear-vs-jira)). → Optimistic UI (already present), keyboard-first.
- **Configuration sprawl / field bloat** — "87 fields to report a bug"; redundant custom fields and workflows fragment data ([Capterra](https://www.capterra.com/p/19319/JIRA/reviews/)). → Keep custom fields few and typed.
- **Needs a dedicated admin** — permissions and automation "often require a dedicated administrator" ([Capterra](https://www.capterra.com/p/19319/JIRA/reviews/)). → Individual owns everything; no admin role in MVP.
- **Cost & billing model** — per-seat, billed for dormant seats (~30% idle), automation quotas that pause rules mid-month, add-ons $3–8/user, Atlassian Guard extra ([resolution.de](https://www.resolution.de/post/jira-pricing-plans/), [Siit](https://www.siit.io/tools/comparison/linear-vs-jira)). → Self-hosted, no quotas.
- **No recurrence, no undo, no work-item trash** — recurring tasks require automation hacks; deleted items are gone forever (see §3 items 11–12).
- **Heavy for small projects / individuals** — "unnecessarily complex for straightforward task management or small teams" ([Capterra](https://www.capterra.com/p/19319/JIRA/reviews/)); reviewers tell individuals to use Todoist/Linear instead ([G2 discussion](https://www.g2.com/discussions/is-jira-a-good-tool)).
- **AI gated behind tiers** — most Rovo features are Standard+ and premium-priced ([Rovo features](https://support.atlassian.com/organization-administration/docs/atlassian-intelligence-features-in-jira-software/)).
- **Context switching with GitHub** — devs resent updating Jira separately from code ([dev.to](https://dev.to/teamcamp/why-developers-hate-jira-and-10-best-jira-alternatives-1hl1)). → CLI + GitHub integration roadmap is well aimed.
